# Recompiled runtime (PS2Recomp): how to run it and what to know

(Docs index in `CLAUDE.md`.) This file keeps what is in use today. The journal of the performance investigations (batched IOP, deferred timers, virtual clock, native VU0) is in `NATIVO.md` ("Physics with `dt`") and in the git history (`git log -- docs/passos/RUNTIME.md`).

## Fast build (without LTCG)
The PS2Recomp release turns on `/GL` + `/LTCG` and the link takes ~28 min on every change. With `-DPS2X_FAST_LINK=ON` (branch `wotm`) the game still runs at 60 fps; incremental rebuild in ~13 s, from scratch in ~4 min.
- **Always use `build_runtime.bat`** at the repo root (or `tools/build_runtime.ps1`): it configures `build_dev` with `-DPS2X_FAST_LINK=ON -DPS2X_ENABLE_AGRESSIVE_LOGS=OFF -DPS2X_ENABLE_IOP_RPC_TRACE=OFF`, touches `ps2_runtime.cpp` (ninja doesn't track `native/`), generates the native VU0 `.inc` when it is missing and compiles. **Two executables** come out in `build_dev\ps2xRuntime\`, from the same objects of the translated game: `wotm.exe` (the game, without emulated GS/VU1/VIF1 and without the check) and `ps2EntryRunner.exe` (test: emulated parts, `WOTM_VU1CHECK`, `WOTM_FOTOS`, `--vu1cmp`; what `corpus.ps1` and `vu1cmp.ps1` use). The clone's `build_dev.bat` compiles both (`--target ps2EntryRunner wotm`). Details in `FRONTEIRA.md`, step 5. `build_runtime.bat nm` does the same for the guinea-pig runtime (`build_dev_nm`).
- **Aggressive logs must stay OFF.** `PS2X_ENABLE_AGRESSIVE_LOGS` comes `ON` upstream: every generated function writes entry/exit with a flush (295 MB in 45 s) and the boot doesn't get past Press Start.
- **The instruction helpers are always inlined:** the register, memory and FPU helpers that the translated code calls on every instruction (`Ps2SetGprLow64`, `Ps2ExtractEpi64`, `Ps2FastRead*`/`Ps2FastWrite*`, `ps2_fpu_fix`, `Ps2IsSpecialAddress`...) are `__forceinline` (`PS2_FORCEINLINE` in `ps2_runtime_macros.h`, `PS2_ADDR_FORCEINLINE` in `ps2_address.h`): in the translated functions, which are huge, MSVC gives up on ordinary inlining and each one would become a call. The rare path (an access that wraps around the end of RAM) stays out of line. `READ*`/`WRITE*` have a shortcut for the scratchpad (16 KB at 0x70000000 and at the mirror 0xF0000000; aligned accesses only), straight into the buffer, without the runtime's `Load`/`Store`; the 32-bit write still serves the completed DMAs, like `Store32`, through an atomic flag (`PS2Memory::hasCompletedDmacCauses`) instead of the mutex. Changing these headers recompiles the game's 169 units (~12 min).
- The build links with `/MAP` and `/DEBUG` (PDB with public symbols only, without `/Zi`; `/OPT:REF /OPT:ICF` keep the binary; `cmake/ReleaseMode.cmake`, `PS2X_FAST_LINK`). `PS2X_HOSTPROF` resolves names through the PDB; to locate a `[CRASH] exe+0x…` without it, look for the largest symbol ≤ the address in `ps2EntryRunner.map`.

## Running
- `run_live.bat` (or `run_live.ps1` in the clone: `-Auto 0` to play, `-Stats 1` logs `[native]`, `-Build build_dev_nm` for the guinea pig, `-Exe test` forces the test one). It runs `wotm.exe`, except with `WOTM_VU1CHECK` or `WOTM_FOTOS` on (`run_live.bat` turns photos on by default; the launcher doesn't), with `-Exe test` or when `wotm.exe` is missing or older: then `ps2EntryRunner.exe`. It sets `PS2X_NO_VU1=1 PS2X_NO_VIF1=1 PS2X_NO_GS=1 PS2X_SCENE=1 PS2X_FMV=1` (emulated VU1 and GS off in the test one, native drawing and movies; `wotm.exe` turns all three on by itself). It uses `Start-Process -RedirectStandardError` on purpose (PowerShell 5's `2>` writes UTF-16). Logs go to `<runtime>\logs\` (`live.err.log`/`live.out.log`; the build writes `build_dev.log` there and `live_attack.ps1` writes `atk.*.log`); the runtime root holds only scripts and folders.
- Direct match without the menu: `WOTM_MATCH=<player>[,<ai>...],<stage>` (0 to 7 AIs; no AI = alone on the stage); AI vs AI: `WOTM_AIVSAI=1`; batch: `tools\lote.ps1` (all of it in `NATIVO.md`).
- Other useful `PS2X_*`: `PS2X_PAD` (button script with timings), `PS2X_DUMP_RAM="3300,3900"` (writes `ram_<frame>.bin`/`vram_<frame>.bin` for the viewer), `PS2X_CD_IMAGE` (ISO), `PS2X_PEEK="hex,hex"` (RDRAM words in the log), `PS2X_HOSTPROF_RAW=1` (with `PS2X_HOSTPROF`: each sample of the EE thread becomes a line `rip w1 w2 ...` in `hostprof_raw.txt`, addresses relative to the exe, to resolve through `wotm.map`, which also has the static functions; the ones outside the exe come out with the name in `#sym` lines; `PS2X_HOSTPROF_SKIP=<s>` discards the first seconds), `PS2X_VU0PROF=1` (in `wotm.exe`, time and calls per VU0 microprogram in the `[time] vu0` line of `PS2X_STATS`; in `ps2EntryRunner.exe` always), `PS2X_HOSTPROF=1` (host RIP sampler, all threads every ~1 ms, `hostprof.txt`; `=2` only the EE thread, or the window's thread with `PS2X_HOSTPROF_WIN=1`; `=3` only the EE thread and only when its frame goes over 100 ms, waking every 50 ms; with `WOTM_FIELDLOG`, a frame over 100 ms comes out as `[hostprof]` with the approximate call chain), `PS2X_COVERAGE` (function coverage), `PS2X_IOP_BATCH` (default 256).
- **Keyboard** (backend in `ps2_pad.cpp`, adds to the gamepad; default map, changeable in the CONTROLS tab of "Recompiled options", `NATIVO.md`, "Rebind"; `kDefaultKb` in `wotm_settings.hpp`): **WASD** = left stick (move; **Alt** walks slowly), **mouse** = camera, **left click** = square (light attack), **right click** = triangle (heavy attack), **Space** = X (jump), **E**/**F** = circle (grab), **Shift** = block, **Q** or middle click = lock-on, **Tab**/**R** or the wheel = next/previous target, **Z**/**C** = strafe, **1** = special (triangle+circle), **2** = special (X+square), **Enter**/**Esc** = Start (pause), **G**/**Ctrl** = Select (taunt), **arrows** = D-pad. In the menus **Esc**, **Backspace** and right click go back, Space or left click confirms. The table in `ps2_pad.cpp` (arrows, I/J/K/L, Space/Z/X/S...) only applies without the native layer. Native layer: **F3** FPS, **F7** pauses and resumes, **F6** (paused) advances one game frame, **F8** takes a photo with a note (with `WOTM_FOTOS`; with `WOTM_VU1CHECK` only, records and compares the next frame). Flow in `VU1CHECK.md`, "Photos".

## Boot trace (black screen before the movie)
From process start to the first movie, the runtime writes each stage to stderr with the time since start and shows the stage on the black screen ("Loading... 3.2 s"). Always on; it stops when the boot finishes. A stage stuck for more than 2 s repeats as `[boot] ... still in "<stage>" for N s (EE PC 0x..., vsync N, R/s)`: map the PC with `config/status.csv`. Measured: window 0.6 s; IOP modules 0.8 s; then the game sits ~3.5 s idle counting vsync at 60/s (the game's own wait; it grows if vsync drops); movie at 4.4 s. Code: `wotmBoot*` in `wotm_live.inc`.

## Useful addresses (menu)
`currScreen` 0x6F8464 (0x14 = Press Start, 1 = menu and also inside the stage, 0x63 = loading), `nextScreen` 0x6F846C, `betweenScreens` 0x6F7E8C, `screenFirstPass` 0x6F7E80, `targetAlpha` 0x6F7E74, `fadingIn/Out` 0x6F807C/0x6F8080, `world` 0x6F87C4, `g_frame` 0x6F7E38. In new code use `wotm::sym::<name>` (`native/wotm_syms.h`).

## Open items
- `PS2X_FAST_BOOT` (skip the opening waits without skipping the initialization).
- The movies' audio follows the wall clock, not the game's.
- Host stalls of 100 to 330 ms outside the fight (`_NLG_Return2`, MSVC stack unwinding) still without a cause.
